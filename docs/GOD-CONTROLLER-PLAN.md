## Four things to decide before Step 2

### 1. `getMyExams` is defined twice in `teacherController.js`

`exports.getMyExams` is assigned at **L1101 (42 lines)** and again at **L1735 (56 lines)**.
The second assignment overwrites the first, so the L1101 body has never executed. Both
`GET /my-exams` (teacherRoutes) and `GET /my-exams` (examControllerRoutes) resolve to the
L1735 version.

**Ask:** extract only L1735 and drop L1101 as dead code? That is my recommendation, but
it is a deletion, so it needs your word.

### 2. Four admin list endpoints overlap existing module controllers — none are identical

| function              | overlaps                                             | difference                                                                                                                                                      |
| --------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getAdminStudents`    | `studentManagementController.getAllStudentsEnhanced` | Enhanced is paginated, filters on `gender`/`category`, `status: {$in:[active,inactive]}`. Admin version is `status:'active'` only, unpaginated, sorts `rollNo`. |
| `getAllStudentsAdmin` | `getAdminStudents`                                   | No status filter at all, sorts `firstName`, no query filters.                                                                                                   |
| `getAdminTeachers`    | `teacherManagementController.getAllTeachersEnhanced` | Same pattern.                                                                                                                                                   |
| `getAllTeachersAdmin` | `getAdminTeachers`                                   | Same pattern.                                                                                                                                                   |

All serve **different URLs** and return **different result sets**. Merging any pair would
change a response body. My recommendation is to move all four verbatim and leave the
overlap documented — but per your rule I am stopping rather than deleting either copy.

### 3. 25 of 106 functions span two or more domains

Your rule says stop and ask on each. Stopping 25 times would stall the work, so the plan
instead assigns each function to the module that owns the data it **writes** (or, for pure
reads, the model the endpoint is actually about), and records the other domains it touches
in the notes column. Cross-module reads go through the sibling module's `index.js`.

The genuinely ambiguous ones, where I do not think the heuristic settles it:

| function                                         | lines     | tension                                                                                                                                                                       |
| ------------------------------------------------ | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getDashboardAnalytics`                          | 141       | Reads Marks, MarksAuditLog, FeeReceipt, StudentFee, Leave, Knowledgecenter, StudentProfile, TeacherProfile, Attendance, FacultyAttendance. Touches 5 modules and writes none. |
| `getTemplateForExam`                             | 349       | Reads report templates and writes nothing, but is driven entirely by exam/marks state. reportcards or examination.                                                            |
| `getCoScholasticMarks` / `saveCoScholasticMarks` | 183 / 142 | Write `CoScholasticMark` (examination) but are shaped by `ReportTemplate` (reportcards).                                                                                      |
| `getMyReport`                                    | 94        | Student-facing aggregate over assignments, marks, leave and attendance.                                                                                                       |
| `deleteSession`                                  | 49        | Cascade-deletes across examination, people and attendance.                                                                                                                    |

**Ask:** accept the primary-owner heuristic for the other 20, and rule on these 5?

### 4. Proposed order

Leaf-first, so no extracted function ever depends on one still sitting in `src-old`:

1. **academics** — 45 functions, mostly small CRUD, no cross-module writes
2. **examination** — 25 functions (includes the two 300-line marks uploaders)
3. **communication** — 18 functions
4. **attendance** — 4 functions (module gains its first service layer)
5. **people** — 11 functions
6. **reportcards** — 3 functions (the largest and most entangled; last on purpose)
